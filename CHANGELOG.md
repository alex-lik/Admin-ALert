# Changelog

Все значимые изменения в этом проекте документируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версионирование — [Semantic Versioning](https://semver.org/lang/ru/).

Версия выводится автоматически из [Conventional Commits](https://www.conventionalcommits.org/ru/v1.0.0/):

| Тип коммита | Эффект на версию |
|---|---|
| `fix:` | patch `0.1.0` → `0.1.1` |
| `feat:` | minor `0.1.0` → `0.2.0` |
| `BREAKING CHANGE:` в теле коммита | major `0.1.0` → `1.0.0` |
| `docs:`, `chore:`, `refactor:`, `test:`, `build:`, `ci:` | версия не меняется |
| `!` после типа/скоупа: `feat(api)!: ...` | major |

Релизы делаются вручную: `python tools/release.py bump --type <t>` → коммит →
тег `vX.Y.Z` → push. Автоматических сборок в проекте нет.

## [Unreleased]

### Added

Сервер — эскалация и доставка:

- Движок эскалации `app/services/escalation.py` (задачи 2.7–2.9): выбор
  просроченных алертов, адресация шага (текущий / следующий / всем с фолбэком,
  задача 2.11), продвижение `current_step`, планирование следующего таймера,
  истечение по лимитам профиля. Воркер `python -m app.worker` подключён к
  движку. Проверено живьём: событие → проход воркера → шаг 1 в истории.
- Профили эскалации (1.2): `python -m app.seed` — `warning`, `critical`,
  `critical-vip`, `local-disk`. Идемпотентный, пригоден для тестов.
- Обработка `resolved` (2.6): входящее событие закрывает алерт и гасит
  таймеры; resolved без истории даёт честный 404, а не выдуманный алерт. Плюс
  ручной `POST /alerts/{id}/resolve` для ложных срабатываний.
- Лимит откладываний по количеству — не больше 2 раз в час на алерт (считается
  по аудиту, отдельный счётчик не нужен).
- `reassign` переоткрывает подтверждённый алерт: чужое подтверждение новый
  владелец не видел. Передача пишется в аудит каналом `reassign`.
- Молчащий телефон push не ждёт — шаг помечается сорванным, следующий наступает
  раньше расписания, эскалация ускоряется в сторону звонка (2.21).
- Отправка push в FCM HTTP v1 (задачи 2.16–2.19): `app/services/push.py`
  (OAuth2 из сервисного аккаунта, RS256-JWT, data-only с `priority: high`,
  разбор ошибок) и `app/services/dispatch.py` (кому, в какой канал, во все
  устройства). Воркер перестал писать `skipped`: шаг помечается `delivered`.
- Уведомление «проблема устранена» при `resolved` — из источника и при ручном
  закрытии. Отправка всегда best-effort после коммита: упавший Google не
  превращает resolve в ошибку.
- Мёртвый push-токен гасит устройство (`UNREGISTERED`, `INVALID_ARGUMENT`,
  `SENDER_ID_MISMATCH` или 404 без кода). Строка не удаляется — вернётся, когда
  админ зайдёт с того же телефона.
- Telegram-канал эскалации (задача 4.8): бот с inline-кнопками «Принял» и
  «15 мин» — дублирующий канал и резервное место для подтверждения. Нажатие
  применяет ту же эскалацию, что и кнопка в приложении: общий сервис, общий
  аудит. Webhook проверяет `X-Telegram-Bot-Api-Secret-Token` постоянным временем;
  после Ack кнопки снимаются, сообщение переписывается.
- Тихие часы (задача 2.13): `app/services/quiet.py`. Ночью `warning` ждёт конца
  окна, `critical` эскалирует как обычно. Окно считается по часовому поясу
  адресата шага, а не сервера, и действует на каждый шаг цепочки — иначе
  `push → telegram → call` разбудила бы ночью и к утру дошла бы до звонка.
  Отложенный алерт не считается обработанным в проходе воркера.
- Миграции: `a7c3e91b2d40` — колонка `admins.telegram_chat_id`.

Клиент:

- Показ уведомления из data-сообщения (`displayAlertNotification`): канал
  выбирает сервер, id уведомления включает alertId (повторный шаг
  перезаписывает уведомление, а не кладёт второе поверх), «устранено» зелёное и
  снимает локальную эскалацию.
- `install.ts` поднимает обработчики push при старте приложения, а не на
  экране — иначе в свёрнутом приложении уведомление показать было бы некому.
- Диагностика различает «FCM не настроен» и «приложение не рисует уведомление» —
  кнопка «Payload с сервера» гоняет настоящий разбор и показ.
- `api/client.ts` — настоящий HTTP-клиент вместо размазанных по экранам
  вызовов, с `ApiError`, который отличает «сеть недоступна» от ответа сервера.
- Карточка Telegram в настройках показывает состояние канала, а не только
  наличие привязки: «бот не создан», «не привязан», «не доходит» — три разные
  поломки с разными причинами.

Зависимости:

- `httpx` и `cryptography` — вторая только ради подписи RS256, которую требует
  Google.
- `tzdata`: на Windows базы IANA-зон нет в системе, и `zoneinfo` падает с
  `ZoneInfoNotFoundError`. Без неё тихие часы и смены дежурства не работали бы
  ни на dev-машине, ни в Windows-деплое.

### Changed

- Вход в приложении делает настоящий `POST /auth/login` вместо local-заглушки.
  Токен живёт в памяти модуля: постоянного хранения пока нет, это задача 3.3
  (нужен react-native-keychain, AsyncStorage читается любым приложением с
  правами на файлы пользователя).
- Список алертов сортируется как на экране — активные → VIP → критичность →
  время (раньше код сортировал только по времени вопреки документу).
- `Dispatcher.send` принимает `step` — по контракту, а не по соглашению.
- APNs-блок собирается, но отправка требует подписи ключом Apple (задачи 1.8,
  1.9). `critical: 1` по умолчанию выключен: без entitlement от Apple FCM
  отвечает `BadPriority` и уведомление не доходит вовсе.

### Fixed

- Воркер готовил текст уведомления из алерта с незагруженными связями: ленивая
  загрузка на `AsyncSession` падает с `MissingGreenlet` ровно в момент отправки.
  То же касается флага `respects_quiet_hours` — он читается до отправки шага.
- Детальные загрузки читали закэшированный состав шагов из сессии вместо БД
  (`populate_existing=True`): после reassign карточка показывала историю без
  шага передачи.
- `Check` не имеет поля `name` — в payload уходило бы исключение вместо имени
  проверки.
- Номер шага в сообщении Telegram показывал предыдущий: `current_step`
  обновляется только после отправки. Номер передаётся в диспетчер явно, и на
  втором шаге дежурный видит «шаг 2», а не «шаг 1».
- Минуты откладывания берутся серверные, а не из `callback_data`: подделав
  нажатие, можно было выпросить откладывание на любой срок.
- Экранирование под HTML-режим Telegram: опасны только `&`, `<`, `>`. Раньше
  считалось, что подчёркивания тоже ломают разметку — это верно для Markdown,
  но не для HTML.
- `python -m app.seed` падал с `MissingGreenlet`: ленивое чтение шагов профиля
  на AsyncSession запрещено. Плюс особая ловушка: у только что созданного
  профиля коллекция шагов не загружена в принципе.
- Новый алерт создавался с `next_action_at=None`, и воркер его никогда бы не
  увидел. Первый таймер взводится при приёме; профиль без шагов даёт немедленный
  таймер, и первый проход признаёт такой алерт истёкшим.
- `ACKED` убран из `TERMINAL_STATES`: подтверждённый алерт переоткрывается
  передачей, он «закрыт, но не терминален». Добавлены переходы
  `ACKED → NOTIFYING` (передача) и `TRIGGERED → EXPIRED` (пустой профиль).
